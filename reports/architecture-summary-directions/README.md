# AI 量化系统架构图 · 三方向初稿

这三张图使用同一套仓库事实，但回答不同的汇报问题。

## A：五层架构

- 回答：系统由哪些层组成，各层职责是什么？
- 优点：最完整，适合技术评审、架构文档和新成员培训。
- 缺点：管理层第一次看时信息密度较高。

## B：决策流水线

- 回答：系统每天如何从数据走到决策，再走到复盘？
- 优点：因果顺序清楚，最容易解释“为什么不是黑箱”。
- 缺点：组件归属和多 Agent 治理不是视觉主角。

## C：双闭环治理

- 回答：系统如何自动进化，同时保证 Agent 不越权？
- 优点：最能突出本系统的核心差异——确定性快环、研究慢环、晋级防火墙。
- 缺点：需要在汇报口头补充各模块的工程落点。

## 共同事实口径

- 系统永久 long-only。
- 快环是确定性 Python 内核，决策时不调用 LLM。
- 多 Agent 仅在慢环提出研究假设、反驳和纪律复盘。
- Agent 不能修改生产内核、不能批准自己晋级、不能直接下单。
- 数据使用不可变快照、UTC `asof`、来源和质量结果；缺失分钟不填充。
- 订单路径使用 P0/P1/P2 guardrails、幂等 OMS 和恢复对账。
- 当前成熟度仍是 `research-only`；Broker 写入默认关闭，kill switch 默认开启。

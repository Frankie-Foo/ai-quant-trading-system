# IBKR 人工实盘执行台

## 先读结论

客户端现在可以通过官方 `ibapi` 连接已经登录的 TWS 或 IB Gateway，并从固定实盘端口
`4001` 提交受限的人工限价单。这不是自动交易功能：研究内核、选股、盘中监控、复盘
和所有 Agent 永远没有下单权限。

执行台是一个仍在工程验证中的安全入口，不能称为完全成熟的券商终端，也不能替代
TWS / IB Gateway 的账户核对、风险控制、订单管理和成交回报。

## 安全契约

| 项目 | 当前行为 |
|---|---|
| 券商连接 | 只连接已登录的 TWS / IB Gateway |
| 端口 | 固定 `4001`，不接受页面或环境变量改成 `4002` |
| 启动状态 | 每次启动默认 `OFF`，写权限默认关闭 |
| 账户 | 首次确认后加密绑定；后续必须精确匹配 |
| 多账户 | 未绑定时只要看到多个账户就失败关闭，不自动选择第一个 |
| 方向 | 只允许 `OpenLong` 和 `ReduceLong`，不允许卖空 |
| 合约 | 只允许美股 `STK / SMART / USD` |
| 订单 | 只允许 `DAY LMT` |
| 自动化 | 研究、Agent、定时任务和监控不能调用执行台 |
| 提交前检查 | 账户刷新、持仓/活动订单核对、IBKR What-If、动态文字确认 |
| 本地账本 | SQLite 持久化幂等键、券商订单号、状态和恢复信息 |
| 状态不确定 | 进入 `recovery_required`，核对完成前禁止新单 |
| 撤单 | 当前不支持；必须在 TWS / IB Gateway 操作 |

## 准备 TWS 或 IB Gateway

1. 使用官方 TWS 或 IB Gateway 完成实盘登录、二次验证和所有账户提示。
2. 在 API 设置中启用 Socket 客户端连接。
3. 将实盘 Socket 端口设为 `4001`。
4. 如果客户端和 TWS 在同一台电脑，优先使用 `127.0.0.1`。
5. 核对受信任 IP、防火墙和 API 只读设置。客户端不能可靠替你判断 TWS 当前是否启用了
   Read-Only API；最终是否接受订单以 IBKR 回报为准。
6. 为客户端使用独立、固定的 Client ID，避免与其他 API 程序冲突。

IBKR 用户名、密码和 MFA 只用于登录官方客户端。不要把它们填入本应用、`.env`、
`quant.env` 或 Git。

## 配置客户端

在“设置 → IBKR 实盘执行”中填写：

- 主机：本机通常为 `127.0.0.1`；
- Client ID：非负整数，且不与其他 API 客户端重复；
- 单笔最大名义金额：美元正数。

端口无需填写，也不能切换；执行台固定使用 `4001`。设置由 Electron 主进程保存，其中
账户绑定信息通过 macOS Keychain 或 Windows 系统安全存储加密。用户名和密码没有配置
字段，也不会被导入。

若从 `quant.env` 或文本文件导入，客户端只识别允许的连接字段；密码、模拟盘字段和
端口 `4002` 不会成为执行配置。

## 首次账户绑定

1. 打开“盈透手动执行台”。
2. 点击“开启实盘执行”。这一步只建立 `4001` 连接，不会解锁下单。
3. 程序读取 TWS 暴露的账户：
   - 只看到一个账户时，页面显示脱敏账户和绑定确认文字；
   - 看到多个账户时返回 `multiple_accounts_require_selection` 并失败关闭；
   - 已经绑定时，券商返回账户必须与密文中的完整账户 ID 精确一致。
4. 在 TWS 中核对真实账户，再输入页面要求的完整绑定确认文字。
5. 绑定成功后本地运行时会重启并回到关闭状态；重新开启连接才能继续。

清除绑定不是撤单动作。清除前应先在 TWS 核对所有活动订单；清除后旧账户中已有的
订单仍可能继续成交。

## 提交一笔人工订单

### 1. 建立连接

打开实盘总开关，确认页面显示：

- 固定端口 `4001`；
- 已连接；
- 账户已绑定且脱敏值正确；
- 没有 `recovery_required`。

### 2. 临时解锁写权限

输入页面给出的动态解锁文字。写权限最长保留五分钟，并会在提交一次、主动关闭、断开
连接或重启客户端后自动关闭。连接成功不等于已经获得下单权限。

### 3. 填写订单

可填写的内容只有：

- 股票代码；
- `OpenLong` 或 `ReduceLong`；
- 正整数股数；
- 大于零的美元限价。

其余字段固定为 `STK / SMART / USD / DAY / LMT`，不能由页面改写。名义金额按
“限价 × 股数”计算，并与设置中的单笔上限比较。`ReduceLong` 还会减去同一股票尚未
完成的卖单数量，避免重复平仓导致卖空；`OpenLong` 遇到同一股票已有活动买单时失败
关闭。

### 4. 生成并检查预览

生成预览时，客户端会刷新账户、持仓和未完成订单，并调用 IBKR What-If。页面会显示：

- 方向、股数和限价；
- 预计佣金；
- 初始保证金变化；
- IBKR 返回的警告；
- 预览有效期和动态确认文字。

如果 IBKR 返回警告，必须先勾选“已阅读并接受”才能继续。What-If 不是成交保证，提交
时客户端还会再次刷新账户、复核订单并重新调用 What-If。

### 5. 动态确认并提交

输入页面给出的动态确认文字。文字绑定账户脱敏值、方向、股数、股票、限价和随机码；
订单内容一旦改变，原预览失效。提交后查看“最近提交订单”，并在 TWS 中核对券商订单号
和最终状态。

## 幂等与恢复

执行账本保存在用户目录的 `research-runs/ibkr-execution.sqlite3`。每笔订单在调用券商前
先写入账本，使用账户、Client ID 和客户端订单号组成幂等边界，并保存 IBKR
`orderRef`、订单号、`permId` 和状态。

典型状态包括：

- `submitting`：已进入提交临界区；
- `submitted`：IBKR 已受理；
- `filled`：已成交；
- `cancelled`：已取消；
- `rejected`：IBKR 明确拒绝；
- `unknown`：发送结果无法确定，不能假定“没有下单”。

如果提交超时、连接中断或进程在临界区退出，系统不会用新的订单号自动重发。重新连接
或点击“核对未知订单”时，会按 `orderRef` 查询活动订单和可用的已完成订单记录。只要
仍有 `submitting` 或 `unknown`，新预览和新提交都会失败关闭。

恢复功能不等于人工确认订单不存在。若客户端仍无法确定，必须在 TWS / IB Gateway
核对订单、成交和账户持仓；不要通过修改客户端订单号来绕过恢复闸门。

## 关闭开关不等于撤单

“关闭实盘执行”、退出 App、保存新连接配置或清除账户绑定会：

- 关闭新订单写权限；
- 清除未提交预览；
- 断开本地 API 连接。

它们不会向 IBKR 发送撤单指令，也不会撤销已经在券商端的 DAY 订单。断开后客户端无法
继续显示券商端的实时变化，但订单仍可能成交。当前版本没有“撤单”“全部撤单”或
“修改订单”按钮；这些操作必须在 TWS / IB Gateway 完成。

## 不支持的功能

- 模拟盘和端口 `4002`；
- 卖空；
- 市价单、止损单、止盈单、追踪单、括号单和 GTC；
- 盘前盘后委托；
- 期权、期货、外汇、加密资产或其他非美股合约；
- 研究信号或 Agent 自动下单；
- 客户端撤单、改单和一键清仓；
- 多账户选择与分配；
- 替代 TWS 的完整订单生命周期管理。

## 排错

### 无法连接端口 4001

按顺序检查：

1. TWS / IB Gateway 是否已经实盘登录并停留在可用状态；
2. 是否启用了 Socket API；
3. 实盘 API 端口是否为 `4001`；
4. 主机是否正确，本机优先 `127.0.0.1`；
5. Client ID 是否被另一个程序占用；
6. 防火墙、受信任 IP 和 TWS 弹出的 API 授权提示是否允许连接。

不要把网页端口、Client Portal Gateway 端口或模拟盘 `4002` 填进这个流程。

### 错误 502

`502` 通常表示 API 无法建立到 TWS / IB Gateway 的连接。常见原因是官方客户端未启动、
尚未完成登录、Socket API 未开启、端口错误或网络策略阻断。修正连接条件后重新打开
实盘开关即可；不要在连接不确定时反复点击订单提交。

### 状态码 2107

`2107` 表示 **IBKR 历史数据通道正在待命，发起历史请求时会自动连接**。这是 IBKR 的
信息通知，不代表客户端的本地历史库缺失，也不是“运行选股时才临时下载全部历史数据”。
客户端的 Massive 存量历史由安装包 bootstrap 预置，之后只补增量；二者是两条独立链路。
适配器不会把 `2107` 当作订单拒绝或连接致命错误。它也不证明交易连接一定正常；仍需
查看后续连接状态、What-If 和明确的订单回报。

### 多账户失败

`multiple_accounts_require_selection` 表示当前 TWS 会话暴露了多个账户。为了避免下到
错误账户，客户端不会自动使用列表第一项。当前版本没有多账户选择器，因此该场景保持
失败关闭。

### 账户不匹配

绑定账户不可见或返回账户与绑定值不一致时，连接会断开，写权限和预览都会清除。先在
TWS 核对登录的实体账户；不要为了绕过错误直接清除绑定。确需换账户时，先核对旧账户
全部挂单和成交，再清除绑定并重新进行首次绑定。

### `recovery_required`

这表示至少一笔订单处于 `submitting` 或 `unknown`。先在 TWS 查询活动订单、已完成订单、
成交和持仓，再点击客户端的恢复按钮。恢复仍不明确时应停止使用执行台，不要重下。

## 上线前最低验收

在真实资金使用前，至少需要在受控账户和极小名义金额下完成：

- 启动默认关闭与五分钟自动锁定验证；
- 错误账户、多个账户和 Client ID 冲突验证；
- What-If 拒绝与确定性拒单验证；
- 提交响应丢失、断线和重启恢复验证；
- SQLite 幂等与重复点击验证；
- 持仓减少、活动卖单预留和禁止卖空验证；
- TWS 人工撤单与成交核对流程演练；
- macOS/Windows 安装包签名和干净机器验收。

这些验收没有完成前，只能把功能视为受限的人工实盘原型，而不是成熟交易终端。

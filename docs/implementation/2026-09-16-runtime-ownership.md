# 美股日内事件模型：运行职责与自动化边界

## 目标与边界

- 仅纽约证券交易所开市日、仅美股、仅 Alpaca Paper、仅做多、当日平仓。
- 每日候选数是上限，不为凑数放宽市值、催化、流动性、点差或数据完整性门槛。
- 任何时间都不由 LLM、Loop 或推送服务直接下单。

## 美东时间运行表

| 时间 | 产物 | 动作 |
| --- | --- | --- |
| 08:30 | `first_wave_pool.json` | 全市场第一轮 Top20。冻结首次市值、催化、盘前量价、相对强度与排序事实。 |
| 09:00 | `second_wave_pool.json` | 全市场重新扫描 Top20。第一轮仍在池内的标的获得一次持续性权重。 |
| 09:30 | `final_wave_pool.json` | 全市场重新扫描 Top10。前两轮重复出现的标的累计加权；开始 Paper 开盘盯盘准备。 |
| 09:35 | `open_decision.json` | 仅用完整 09:30–09:35 的 5 分钟 K 复核；通过后才生成冻结预案并启动 Paper 监控。 |
| 09:56 后 | `paper-state.sqlite3` | 仅当 H15、上升 VWAP、量价、点差、风险与保护单全部通过时，提交 Alpaca Paper 订单。 |
| 10:00–15:00 | 通知账本 | 每小时推送一次事实状态；成交另行即时推送。 |
| 15:00 | Paper 监控 | 禁止新开仓或加仓。 |
| 15:50 前 | Paper 监控 | 取消未成交入场单并清空当日持仓。 |
| 收盘后 | Postmarket 与 Loop | 生成复盘、记录结论、上传 Loop；不产生新订单。 |

`repeat_count` 只由已冻结的较早波次是否出现计算；`weighted_score = base_score + repeat_count`。09:00 最多得到一次加权，09:30 最多得到两次加权。它奖励持续出现，不替代实时流动性、价格结构或风险门槛。

## 三类职责

| 层 | 可做 | 不可做 |
| --- | --- | --- |
| API | Alpaca SIP 提供报价与 K 线；新闻、公告与 SEC 来源提供事实；Alpaca Paper 提供账户、订单、成交和保护单接口；Loop 接收复盘与候选策略。 | API 返回不等于交易信号；Loop 不能授权订单。 |
| 确定性脚本 | 数据质量校验、硬门槛、Top20/Top20/Top10、重复加权、开盘确认、H15、仓位、止损、止盈、撤单、清仓、幂等、审计、复盘和 Loop 同步。 | 不猜测缺失数据，不用收盘后的赢家反推盘前候选。 |
| LLM | 基于已保存新闻与公告做催化分类、中文解释、复盘归因、提出 Challenger 策略。 | 不决定实时排名，不填价格/成交，不绕过硬门槛，不计算仓位，不写入券商。 |

## 交易授权链

1. API 和脚本生成并冻结三轮候选事实。
2. 09:35 的完整开盘 K 通过后，脚本写入完整中文预案和 `open_confirmation.json`。
3. 唯一可写券商模块是 Paper 监控脚本；它在提交前再次检查报价年龄、点差、账户、杀手开关、风险、保护止损和幂等订单 ID。
4. 首次尝试与一次二次入场分别使用 60% / 40% 风险额度；全包止损不超过 2%，目标为 3R 或趋势退出。
5. 无候选或任一检查失败时，写入 `open_no_trade.json`，不强行下单。

## Loop 的事实边界

每日复盘上传 `intraday_waves`：08:30、09:00、09:30 三份冻结快照及其 SHA-256、候选数、排序和重复权重。

- 有真实盘中冻结候选池时，Loop 标记 `frozen_intraday_pool`。
- 没有可执行预案或券商成交时，Loop 只接收 `post_close_research_only` 研究复盘，且显式禁止订单执行。
- 盘后涨幅榜只用于发现与评估因子，不可伪装成早盘信号或回写当日交易决定。

## 单一运行所有权

- `Trading System V2 - AI Quant Funnel`：每分钟触发一次，只在上表时间窗口执行；负责三轮候选、开盘确认、Paper 启动和每小时状态推送。
- `Trading System V2 - Postmarket Review`：收盘后执行复盘与 Loop 同步。
- 旧 Premarket 与旧 Paper Session 任务必须保持禁用，避免重复选股、重复下单或重复推送。

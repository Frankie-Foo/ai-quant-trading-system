# 2026-09-22 VPS 记录与 Loop 恢复修复

## 范围

本轮不改选股条件、风险额度和交易权限，不提交测试订单，不把测试样本送入生产复盘。
生产仍仅允许 Alpaca Paper。VPS 多维表是记录投影，不是交易授权来源。

## 修复与测试

1. 缺少投资记录 provider 时直接报错，不再默认使用旧飞书。
2. 投资记录先冻结整批内容，再尝试发送。断线后按原 event_id 和原内容补写；
   远端追加结果不明时，只做读回核对，不盲目重复追加。
3. 成交推送、成交表、盯盘表各自保留回执。某张表失败不撤销已发送消息，
   恢复后不重复推送成交。缺少成交时间时使用持久化观察时间，不使用重试当前时间。
4. 盯盘状态记录包含观察、入场阻断、入场意图、持仓保护、退出、结束和实际成交。
   本地状态与状态事件原子保存；重复状态不产生行情轮询记录。
5. Loop 在创建 task / run 前保存请求意图，获得 ID 后立即持久化。
   异步运行只查询原 run；不把处理中写成成功。并发的晚到本地拒绝不得覆盖已认领请求。
6. Loop 恢复先查原交易日持久事件，不依赖当前策略、原始文件或重新生成的快照。
   分钟维护任务执行到期查询，失败按 1/5/15/60 分钟退避。
7. 无法确定 POST 是否成功时要求核对，不重复 POST。终态失败不自动创建新任务。

回归覆盖：配置缺失、整批冻结、读取失败、追加超时、进程重启、内容冲突、
成交推送去重、无成交状态、并发认领、晚到拒绝、输入文件缺失、异步完成与退避。

## 实际接口验证边界

- 只读检查：Alpaca Paper ACTIVE；VPS selection/monitor/trade/review 四表可读；
  Livermore 频道可访问。该检查订单、记录和消息写入均为 0。
- Loop 当前凭据可以读取任务列表和 `GET /api/v1/tasks/{task_id}`；实际只读检查分别
  得到 `COMPLETED` 和 `FAILED` 终态。直接读取 `/api/v1/runs/{run_id}` 不属于当前公开
  契约并返回 HTTP 403，因此恢复逻辑按接入手册查询原 Task，同时保留原 run_id 回执。
  只有 Task 返回 `COMPLETED` 才记录远端完成。
- Outcome 自动回填仍因缺少已批准成本模型配置而关闭；没有编造批准人与成本参数。
- 单元测试与安全演练不证明策略收益，也不保证未来没有故障。

## 上线检查与回滚

使用合入 main 的固定提交，复用现有持久 runs 与投资记录数据库；不得启用空账本。
备份任务 XML、Loop/VPS 数据库，暂停并排空当前调度，确认无未归属持仓/订单后切换。
所有进程使用隐藏窗口。保留上一发布目录和任务备份；回滚不能删除新产生的账本事件。

VPS 队列迁移只新增表；Loop 仅新增重试列；Paper 复用现有 outbox。
未将账户授权、已批准策略或风险上限作为修复的一部分修改。

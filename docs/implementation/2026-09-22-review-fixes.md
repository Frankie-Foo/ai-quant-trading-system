## 第二轮续修：已解决的重要发现

### P1：每轮受旧隔夜新闻池限制（已修）

`scripts/run_modern_funnel_stage.py::_refresh_selection_inputs` 更新量价和市值，但 `build_selection_gates.py::_load_locked` 仍读取 `overnight_candidates`。`build_catalyst_snapshot.py` 默认新闻截止北京时间 08:00，之后显式 `--asof` 仅做旧名单验证，不能纳入名单外新事件。因此，本次没有实现盘前新增事件的全市场动态发现。

现已为每轮生成独立 `kernel.catalysts.wave_candidates` 快照，刷新日线预筛股票集合内的新事件，不局限旧名单。新闻发布时间与修订时间不得晚于本轮截止；快照可用时间保留真实落盘时间，不能回填成新闻截止时间。

候选 → RVOL → SIP 市值 → gates → forward pool → 开盘冻结池，全链传递明确的快照 ID，校验内容哈希、来源、可用时间和父 ID；gates 还校验 RVOL 日期、截止时间、唯一标的及日线来源。合法空池直接结束当前轮，不读旧池补数。

新增 `schedule.premarket --reference-only`，使用独立任务账本键，只准备日线/证券参考数据，不先执行旧隔夜新闻锁，也不误标旧锁任务完成。现有 `--lock-only` 和独立旧 CLI 行为保留。

### P2：跨轮输入缺少日期、时序与父文件哈希校验（已修）

`_prior_candidates` 只检查列表结构，第二、三轮缺少父快照 SHA256 关联。错日、未来或被替换的前轮 JSON 可能参与重复加权。

现通过 `operations.wave_artifacts.read_wave_artifact` 递归校验交易日、阶段、带时区生成时间、父子顺序，以及 `prior_wave_hashes`。第二轮绑定第一轮；最终排名绑定前两轮；开盘决策绑定最终排名。来源校验失败时抛出错误，交由既有调度失败/报警路径处理，不授权新仓。

不为旧历史文件补造来源证明。旧文件若缺证据，不能用于新的开仓授权；已有合法 `open_confirmation` 的同日恢复路径不依赖重新生成前轮文件，持仓保护不被此次迁移阻断。

# 事件量化模块实施与待确认测试

用户要求：先完成模块实现；到测试阶段写好流程，停止等待确认。Astra medium 只负责实现，测试不使用 Astra。本轮不运行 pytest、检查器、回放、模拟撮合或外部联调。

## 本轮实施范围

1. M1：追加事件账本、保留消息修订与实际录入时间、动态事件样本、已有新闻格式导入适配器。
2. M2：决策时可见的完整 K 线特征、10—15 点区间排名、事件响应标签、带明确假设的成本计算。
3. M3：全事件因子统计与近期热度。实验持久化、盲测使用锁及研究 CLI 尚未实现，既有 registry 保持原样。

各模块在独立工作树实现后汇入事件开发树。现有生产任务和账户保持原配置；此文不代表模块通过验证或已经上线。

## 测试流程草案

确认后由 Sol high 编写和审查测试，固定脚本执行。每一步失败先记录具体输入和预期，不改变数据来凑通过。

### M1

详见 `2026-09-14-m1-test-plan.md`：从公共接口验证持久化、重启、重复导入、事务回滚、晚到新闻、重大修订、转载聚类、研究来源隔离和动态新标的。

### M2

- 用手算固定样本验证完整 K 边界、H15/H30、VWAP 与斜率；加入一根尚未完成或晚到 K 线，之前的决策结果不变。
- P10/P15 分别只允许边界之前 60 秒内的有效成交；未来价、过期价、不同 feed/复权口径不能混算。并列名次顺序稳定。
- 14:40 开始的 30/60 分钟标签标记删失；到期前标未成熟；缺行情留空，不写 0 收益。
- 买 ask、卖 bid，佣金按每个订单应用最低值；已通过买卖价体现的 spread 不重复扣除。实际成交与研究回放收益区分来源。
- 检查输入行重排、重复记录、时区变化、半日市、数据断档时的明确结果。

### M3

- 混合上涨、下跌、无反应、缺失样本，验证有效样本与缺失计数、胜率和盈亏比。
- 同事件重复导入不增加独立样本；冲突内容明确拒绝。盘后赢家集合不能冒充全部事件样本。
- 用明确交易日列表计算 3/5/10/60 日窗口；冻结时点之后的消息、标签和修订不能改变旧统计。
- 稀疏分组显示收缩依据和不足原因；未知成本、缺少覆盖或未估计置信区间不能自动晋级。
- 若实验登记模块落地，验证失败实验留档、分割不重叠、盲测使用次数和不可变记录。

### 集成

先运行新增模块公共接口测试，再运行旧 catalyst/event_cohort/quote_costs/registry 相关回归。只有接入交易或 Loop 后，才增加相应端到端测试；未接入的链路不声称验证完成。最终记录命令、版本、退出码、缺陷和剩余限制。

## 后续依赖

历史市值与股本的 as-of 对齐、真实新闻覆盖、成熟标签、完整成本证据和远端契约，需要在接入阶段逐项落实。M4 执行、M5 调度复盘、M6 远端回传、M7 晋级灰度仍按总设计推进；未验证的新模块不能直接替换正在运行的交易链。

# ADR 0002：事件驱动策略的候选配置与渐进接入

- 状态：实施中，尚未启用执行
- 日期：2026-09-14
- 用户确认的实施模型：GPT-6 Astra / medium

## 决策

新策略使用独立、不可变、严格校验的事件策略配置；默认仅 shadow。
先验证配置、内容哈希、风险预算及 NYSE 会话时刻，再逐步接入研究与交易。
`kernel/event_policy.py` 是新的候选配置公共接口，不自动替换现有 Modern H15 的
`PaperRuntimePolicy` 或改写 `active.json`。当前不会有两个自动券商写入者。

保留 ADR 0001 的 Paper-only、唯一 writer、专用飞书和预案回执要求。
动态候选池是后续策略接入的目标；本次配置接口不授予盘中新股下单权限。
200,000 美元是策略额度上限，还受开盘/当前账户净值、剩余风险和现金约束，
不是账户重置目标，也不是按券商杠杆购买力决定的仓位。

## 基线处理

main 与 feature/loop 已分叉；不能以 feature/loop 整树替换 main。
合并必须保留 main 中已存在的真实成交证据、未知收益为空、Paper 幂等保护，
并纳入 feature/loop 的决策意图、Top10 同组、信号和时间线校验。

活动发布目录另有未提交修改。其路径与内容哈希见
`docs/implementation/2026-09-14-baseline.json`。盘点记录不是备份或部署证明。
所有未迁入修改必须逐项核对、回归并记录取舍后，才能更换线上发布路径。
只读检查计划任务的 Ready 状态不代表任务执行成功。

## 验收

配置公共接口测试必须拒绝无效数值、未知字段、越界风险和不一致版本。
正常日、半日市和夏冬令时按明确的交易日历会话输入计算；拒绝无时区时间。
完成候选配置测试不代表所有消费者已经读取统一策略，更不代表策略盈利。
上线必须另有接入测试、订单与故障演练、完整证据、灰度和回滚验收。

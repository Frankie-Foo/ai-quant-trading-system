# 美股事件驱动自主交易系统：设计与实施计划

> 版本：设计稿 v1.0｜日期：2026-09-14｜状态：用户已确认 Astra medium，实施进行中。本文是拟议设置，不是已部署报告；不包含实盘下单授权。

**目标：** 从“按时筛选、等待固定形态”升级为“持续发现事件、估计可交易净收益、自主执行、每日归因复盘、受控迭代”的美股日内做多系统。盈利必须由未参与调参的数据与前向运行验证，不能由设计或模型承诺。

**架构：** 复用现有模块化单体、数据存储、Paper 订单适配器、通知和 Loop outbox；更换选股决策与研究闭环，不重写整套基础设施，不新增微服务或多个券商写入进程。

**技术栈：** 现有 Python 3.12、Polars、Pydantic、SQLite、Parquet、pytest、Windows Task Scheduler；保持仓库锁定依赖。AI 在数据适配与研究层工作，确定性交易内核不调用大模型。

**实施负责人：** 建议 GPT-6 Astra，推理强度 medium。确认后按下述里程碑实施；实施在独立开发工作树内进行；上线前不修改计划任务、券商连接或线上策略。

## 2. 目标与授权边界

### 2.1 三层目标

1. 运行目标：交易日自动启动、获取数据、识别机会、生成预案、按条件执行、退出、复盘和同步；无需用户每天催。
2. 研究目标：找出哪些事件在什么时间和价格状态下，扣除成本仍有正期望。发现强势股和赚到可执行利润分别考核。
3. 经济目标：样本外及前向 Paper 的成本调整净期望为正，回撤和容量可接受；不设“每天必须买入”或“每天必须盈利”。

### 2.2 运行权限

- 首次交付的自动执行仅指 Alpaca Paper。IBKR/其他实盘连接不接入自动写单链；以后实盘是独立上线关卡，需要账户、额度和授权。
- 巴菲特只读观察与用户提供的实际成交具有研究价值，可进入复盘，但保留来源字段，不能改装为自动策略的历史信号或成交。
- 未验证新策略允许全市场影子观察与历史回放，不允许被标为已盈利策略。没有通过验证的策略时，系统持续研究、保持空仓。
- 此设计中的新增阈值属于待实施的 v1 建议。用户确认启动实施后写入候选配置；上线前打印实际生效值与差异，不能静默覆盖线上配置。

## 3. 一条完整的闭环

```text
新闻与行情 → 当时可见的事件/状态 → 交易价值评估 → 结构确认
                                                    ↓
每日复盘 ← 券商对账 ← 受保护的订单与退出 ← 风险预算/预案回执
    ↓
本地经验库 + Loop 同步 → 候选策略 → 时间切分回测/压力测试
                                      ↓
                             影子验证 → Paper 灰度
                                      ↓
                               新版本或回滚
```

旧 H15 保留为对照策略，不再拥有唯一入场解释权。第一版只研究两条路线：突破后首次回踩承接、事件后趋势延续。先用同一退出与成本规则比较入场，避免同时改变十几个变量。

## 4. 每日运行时刻与持续观察

所有交易时刻以 America/New_York 为准，存储使用 UTC；北京时间只用于显示与凭据访问限制。美股休市不交易、不发例行消息。夏冬令时由交易日历换算，不固定写死北京时间。

| 美东时间 | 任务 | 下单权限 |
| --- | --- | --- |
| 09:00 | 检查交易日、时钟、凭据权限、Paper 账户、仓位、工作树、policy、kill-switch；读取全市场事件池，发第一波最多 10 只及中文理由 | 无 |
| 09:25 | 更新盘前量价、消息有效性、相对强弱，形成优先关注名单；不是永久删除其他标的 | 无 |
| 09:35 | 完整开盘 5 分钟观察与风险提示，启动观察状态机；H15 此时尚未完整，不能伪造 H15 确认 | 无 |
| 10:00—15:00 | 持续扫描新事件和状态；符合条件时动态生成预案，取得回执后执行；同一事件/决策不重复推送 | 有条件 Paper |
| 15:00 | 禁止新开仓、加仓及二次入场；撤销仍活动的入场单，确认撤单 | 仅退出 |
| 15:45 | 复查未成交买单、部分成交及保护单；启动强制清仓流程 | 仅退出 |
| 15:50 前 | 完成平仓并对账；停牌无法成交则高优先级报警、持续处理，不谎报空仓 | 仅退出 |
| 16:00 | 生成盘后初报与 10:00—15:00 Top10，启动券商对账 | 无新交易 |

| 盘后 | 回填成熟标签、更新次日 3/5/10 日统计、检查漂移；每周一次候选实验 | 无新交易 |

09:00 ET 对应夏令时北京时间 21:00、冬令时 22:00，满足用户“北京时间晚上九点后才允许调用该 SIP 凭据”的限制。20:00 北京时间只能做不涉及受限凭据的静态准备，不提前下载 SIP。凭据窗口由现有许可检查器统一执行；未获许可的历史数据补采也等待许可窗口。

半日市：入场截止改为 min(15:00, 官方收盘前 60 分钟)，强平截止为官方收盘前 10 分钟。10:00—15:00 完整统计窗口不存在时单独标为短交易日，不混入完整日 Top10 和 60 分钟标签。

行情优先流式订阅，交易状态本地每秒检查；1 分钟/5 分钟特征只在 K 线完成后更新。新闻默认每 60 秒拉取并增量去重，断流按供应商限频重连。不每秒向飞书写行情，不靠新建聊天任务维持盯盘。

## 5. 股票池和发现机制

### 5.1 两个股票池，三种名单

- 发现宇宙：可获得可靠行情的美国主要交易所普通股及 ADR，剔除 ETF、杠杆产品、OTC、权证等不同机制产品。全市场覆盖率必须报告；数据只覆盖一部分时不能宣称全市场 Top10。
- 交易宇宙：发现宇宙内，决策时可验证市值至少 10 亿美元、股价至少 2 美元、正常交易、可做多且可取得新鲜 SIP 报价的标的。使用当时可知的股本/公司行动资料，不用今天市值替换历史市值。
- 盘前前 10 只：人类阅读的简洁关注名单，允许不足 10 只。
- 盘中候选：所有被捕获且当时满足交易宇宙的新事件，不限于盘前名单；允许动态入池、重新排序和恢复观察。
- 盘后 Top10：10:00—15:00 区间涨幅排名，只用于发现热点与检查漏选，不是盘中预选池，也不作为训练样本全集。

### 5.2 排名与入场分开

真实催化、盘中相对强度、RVOL、VWAP 距离、已上涨幅度、回踩形态用于估计交易价值与排序。原有“涨幅至少 4%”“RVOL 固定大于 3”“beta 大于 1.5”等不直接继承为全系统硬门槛；保留在旧策略对照中，通过消融验证决定是否有增益。

安全门槛仍为硬门槛：行情时效、可执行成本、数据可追溯、Paper 端点、账户与保护单、预算、时段。不能为了买进去而移除安全检查。

候选暂时不合格要标记下一次复核条件，例如“点差恢复后重查”“下一根完成 K 线确认”“新消息实质变化后重查”；不是一次拒绝就删除全天。确认是假消息、退市或数据来源损坏时终止该事件。

## 6. 数据契约与防未来函数

| 记录 | 主键与关键字段 | 约束 |
| --- | --- | --- |
| Event | event_id、revision、symbol、source_url、source_type、published_at、first_seen_at、body_hash、event_cluster_id | 保留原文版本；转载聚类，不把同一条消息当多个独立样本 |
| Attribution | event_id/revision、primary_factor、secondary_tags、confidence、evidence_spans、classified_at、prompt/model/version/hash | 主因允许“未知/多因素无法区分”；置信度不是盈利概率 |
| FeatureSnapshot | snapshot_id、asof、available_at、完成 K 线边界、行情 feed、特征值、输入 hash、coverage | 所有输入 available_at 不晚于 decision_at；未完成 K 不准进入完成 K 特征 |
| Decision | decision_id、event_id、snapshot_id、policy_id、决策时间、机会评分、action、原因、复核触发、plan_id | 观察/拒绝也保存；分清研究、影子、Paper、人工来源 |
| Execution | client_order_id、broker_order_id、fill_id、parent/leg、side、qty、price、时间、状态、费用证据 | 券商回执为事实；未回执状态不得当作拒单或成交 |
| Outcome | decision_id、label_version、horizon、matured_at、net_return、MFE、MAE、censor/missing_reason、cost_id | 实际、回放、未成交反事实分账；缺数据不记为零收益 |
| Review/Sync | trade_date、revision、cohort_hash、输入 manifest、对账状态、outbox_id、task/run_id、远端状态 | 修订追加、不覆盖；HTTP 成功不等于远端复盘成功 |

可决策时间至少为 max(消息首见、归因完成、所需行情/特征可用时间)。原文发布时间早，不代表本系统当时已获得它。历史首见时间缺失的事件只能用于带限制的研究，不能伪称完整可执行历史。

新闻发布时间早于启动只是必要证据，不证明因果。盘后才发表的解释不能写入当日启动前的主因。AI 只接收截止时刻之前的原文与状态；隔离联网与券商权限，拒绝原文中的指令。历史归因还须标记模型训练知识可能带来的事后认知污染，关键盲测用冻结文本、引用核验及前向归因补证。

同一事件的后续重大修订形成新 revision，并记录新的可用时间；不能把下午修订后的利好内容套在上午版本上。历史手工补录同时保存实际录入时间和原始交易时间，不倒写 asof。

## 7. 统一收益、标签和成本口径

### 7.1 Top10

完整交易日区间收益 = P15 / P10 - 1。P10、P15 分别取不晚于 10:00:00、15:00:00 的最近有效成交价，最大回看 60 秒；缺失则该标的区间收益不可用。边界价同 feed、同公司行动口径。极值涨幅单列，不能用区间最低买入最高卖出冒充可交易收益。

全市场 Top10 与可交易市值池 Top10 各保存 cohort_id；主报告标明哪一个。不得用盘后 Top10 替换早盘冻结池，以便通过远端数量校验。

### 7.2 两组标签

- 事件响应：从系统首次能够识别事件的时刻出发，统计 15/30/60 分钟方向、反应强度及回落。回答“消息是否带来后续反应”。
- 交易响应：从策略决策后首个可执行入场开始，按照冻结退出规则和成本计算收益。回答“这笔做多是否值得”。实际成交使用真实 fill。
- 标准研究机会在事件识别后首个完整分钟决策点建立；后续仅在候选状态切换时建新决策。相邻分钟不得无限复制一个事件来放大样本量。误差估计按事件/股票/交易日聚类。
- 统计窗口只到 15:00。14:40 的 30/60 分钟完整标签为右删失，不接隔夜、不硬缩成同名标签；可另存到 15:00 的截尾收益。实际持仓按其退出规则统计，最晚 15:50，和研究窗口标签分开。
- 成熟标签不足、停牌、缺报价、缺成交路径分别编码；展示缺失比例。没有涨、下跌、冲高回落才是有效负样本，不把供应商失败当作亏损。

### 7.3 成本与真实性

Paper 原始成交收益与“成本调整后的评估收益”双列。真实 fill 已包含的买卖价差和滑点不能重复扣；只对券商未模拟/未记入的费用与执行偏差做明确附加调整。回放从 ask 买入、bid 卖出，再加滑点、手续费和冲击成本，不再额外重复减一次完整 spread。

拟议研究成本模型 ID：us_intraday_conservative.v1。它不是已有批准版本。佣金暂用仓库既有保守假设每股每边 0.0035 美元、每单每边最低 0.35 美元，仅用于研究；实际券商费率/监管费依据可追溯生效表与流水。没有该历史费表的样本标为成本不完整，不进入正式盈利验收。

滑点按同流动性组已有历史观察的 P95 估计；样本不足时研究暂用每边 10bp 附加滑点，并分别跑每边 25bp 压力情景。它们是保守假设，不叫“真实滑点”。风险预留至少按第 10 节的 0.5% 全包准备；若估计需要更多，缩小可容许结构止损或拒绝交易，不压低假设凑门槛。

Paper 不完整模拟市场冲击、延迟滑点和排队等，且撮合数量可能超过实际 NBBO 可用量，因此 Paper 盈利不能直接认定实盘盈利。[Alpaca Paper 官方说明](https://docs.alpaca.markets/us/docs/paper-trading)

## 8. 因子学习：热度和交易优势分开

### 8.1 热度

最近 3、5、10 个交易日各计算一次。每日 Top10 权重建议为 (11 - rank) / 55，乘以 min(正区间涨幅, 30%)；按主因汇总并显示原始事件数。此处 30% 仅是初始统计截断参数，固定登记后再验证，不能看到 AMLX 等结果后临时修改。

### 8.2 交易优势

用被捕获的全体同类事件，包括上涨、下跌、无反应和高开失败，统计：15/30/60 分钟上涨概率、盈利概率、均值/中位净收益、平均盈利/平均亏损、PF、MFE、MAE、回落比例、样本量、独立交易日数、95% 区间与成本后期望。

使用至少 60 个交易日的较长基线，3/5/10 日只作近期偏移。不能靠 3 天 4 笔就认定新优势。v1 使用分层分组估计，稀疏状态向因子级、市场级收缩；不把事件×时刻×涨幅×量能全部交叉成海量小格子。

研究先验权重 n/(n+30) 作为登记的候选起点，正式权重只从训练/验证集确定。正式决策不得读取当日尚未成熟标签；生产统计模型每天开盘前冻结，盘中只更新事件和特征。

### 8.3 第一版状态特征

- 事件：类型、来源等级、原文证据、首见延迟、消息距离现在多久、重大修订。
- 价格：相对前收涨幅、跳空、距 VWAP/H15/H30、日内波动尺度、回踩深度、完成 K 线高低点结构。
- 量能：同一时刻历史 RVOL、成交额、上涨与回踩量比；不能把午后累计量和早盘累计量直接比。
- 相对强弱：个股相对板块、板块相对 SPY；科技主题另展示 QQQ，不用今天才知道的板块分类倒填历史。
- 趋势：VWAP 斜率；EMA20/EMA50 和斜率先作为候选辅助因子，不增加未经验证的均线硬门槛。
- 成本：最新 spread、报价年龄、滚动成交额、容量、滑点估计、结构止损到入场距离。

决定是否交易看条件净期望及不确定性，再看结构触发和安全门槛。LLM 不直接输出一个未经校准的“上涨概率”指挥买入；v1 统计模型必须能逐笔解释采用了哪个组、哪些样本和何种收缩。

候选进入结构观察的统计规则：已获准运行的策略版本、状态没有超出训练覆盖、收缩后的成本净期望 >0。局部状态少于 30 个独立事件或少于 5 个交易日时回退到有证据的因子级/市场级，不强求每个小格子的置信下界都为正；连上级证据也不足则仅影子观察。完整策略的盈利置信要求在第 14 节统一验收，不能拿当日噪声临时晋级。归因未知的事件留在发现与研究库，v1 不靠未知主因自动交易。

## 9. 入场、退出与二次入场的 v1 规则

### 9.1 首次回踩承接路线

只在 10:00 后使用完整 5 分钟 K。事件已被识别，价格位于 VWAP 上方且 VWAP 相比三个完成 5 分钟区间前上升；最近一次向上突破已发生，随后回踩至突破位、VWAP 或确认的更高低点附近。位置距离以训练集冻结的波动尺度判断，不用任意美元常数。

回踩量小于此前推进段的平均每根 K 成交量；回踩未破已确认结构低点。确认 K 收盘突破前一根完成回踩 K 的高点，低点抬高，成交量至少为前一 K 的 80%。买入发生在确认 K 完成并计算完成之后，绝不回填到该 K 的最低价或收盘之前。

H15/H30 可作为结构参考，不能在构造时间前读取。第二条事件趋势延续路线作为同框架候选做对照，不在首个发布版本临盘随意混用。

### 9.2 预案、入场与过期

每次实际入场前生成中文机器可读预案：事件证据、条件优势、触发、动态参考价/最大接受价、止损、3R 目标、最大持仓时间、风险份额、数量、失效条件、15:00/15:50 规则和策略版本。写专用飞书并取得 Livermore 推送回执，随后刷新报价并再检查风险；发送预案不代表成交。

最大接受价按确认时参考价上方 0.25% 与风险允许价的较小者确定。报价 spread ≤0.25%、年龄 ≤2 秒；满足时用现有受保护入场适配器提交可成交限价 bracket。30 秒未成交则撤销剩余，先对账再允许新信号；不能无限提高限价。预案超过一个 5 分钟区间或结构失效即过期，需要新版本。

消息队列拥堵导致错过买点要记录“预案回执延迟”，不能绕过回执。盘中新增候选首次形成可执行预案时允许推送；不推每次观察波动。

### 9.3 退出

- 结构止损：最近已确认更高低点下方留至少一个有效 tick；不因亏损扩大止损。实际 stop 价格需由当时结构计算。
- 固定收益目标：价格风险的 3R；同时显示扣除成本后的净 R。不是把目标 3R 当作已实现平均盈亏比。
- 趋势退出：连续两根完整 5 分钟 K 收在 VWAP 下方，同时形成更低高点和更低低点。
- 时间退出：v1 最长持仓 60 分钟或到强平时间，以先到者为准；更长趋势持有单独实验。
- 任一保护退出先发生即执行；止损本地每秒检查作为补充，券商端保护单是主要后备。

止损单无法保证极端跳空或停牌后的成交价格，“全包 2%”是事前风险预算限制，不是最大实际亏损保证。[Alpaca 订单说明](https://docs.alpaca.markets/us/docs/orders-at-alpaca)

### 9.4 一次二次入场

单票同一交易日最多两次，无新预算重置；首次止损后可继续观察。只有重新站回 H15 与上升 VWAP、形成更高低点、完整确认 K 放量突破局部高点，且事件未失效时允许第二次。第二次仍需新预案、独立订单 ID、完整保护和新的成本检查。

首次最多使用该单票风险额度的 60%，第二次最多 40%；第二次风险还受“原额度减去首次实际损失与已消耗成本”的限制。首次盈利不使预算无限扩张。v1 不再另开日内侦察或自动加仓路线，避免和两次入场混用。

## 10. 资金和风控：统一拟议设置

| 设置 | v1 值/计算 | 说明 |
| --- | --- | --- |
| 目标策略资金 | 200,000 美元上限 | 不重置券商账户；实际预算取该上限与账户可用净值较小者 |
| 单票单日总风险 | 风险基数的 0.5% | 包含两次尝试；20 万基数时合计最多 1,000 美元 |
| 风险基数 | min(20 万、当日开盘净值、当前净值) | 当日盈利不自动扩大风险，亏损会缩小风险 |
| 两次份额 | 60% / 40% | 20 万基数首次最多 600、二次最多 400 美元 |
| 全包入场止损预算 | ≤入场名义金额的 2% | 结构距离 + 费用/点差/滑点准备，按实际剩余预算反算 |
| 成本准备 | 至少名义金额的 0.5%，估计更高用更高 | 不是声称滑点一定 0.5%；低估不可通过改配置掩盖 |
| 单票名义金额 | ≤策略风险基数的 35% | 新增拟议分散上限；不是必须配满 |
| 同时持仓 | 最多 3 只 | 先最强，再按剩余风险和资金排序 |
| 总名义敞口 | ≤风险基数 100% | 含未成交买单预留；不按 4 倍购买力放杠杆 |
| 同主题总风险 | ≤风险基数 0.75% | 存储链等相关股合并；第二只须第一只已有浮盈 |
| 全账户并行计划风险 | ≤风险基数 1.5% | 与单票、同主题、日亏限制同时满足 |
| 当日亏损闸门 | 风险基数 1.5% | 已实现损失 + 当前浮亏 + 未计成本；触发后当日不再开仓，撤入场并有序退出 |
| 入场报价 | SIP ≤2 秒，spread ≤0.25% | spread=(ask-bid)/mid；异常交叉报价不可用 |
| 容量 | 新单股数不超过前一完整 1 分钟成交量的 1% | v1 保守参与率；不能靠 Paper 无限撮合验证 20 万容量 |
| 入场/退出时刻 | 10:00—15:00 入场；15:50 前平仓 | 半日市按收盘相对偏移；不持隔夜是目标，异常必须报警 |

股数 = floor(min(可用风险金额 / 每股全包止损成本, 单票名义上限 / 最大接受价, 剩余总敞口 / 最大接受价, 可用现金 / 最大接受价, 容量允许股数))。每股成本含佣金最低收费对数量的影响，采用离散求解后复核，而不是只用价差分母。

可用风险金额取尝试份额、原单票剩余预算、同主题剩余预算、并行风险余量、当日日亏剩余预算的最小值；日亏余量需扣除已发生损失与在途/持仓风险，不能损失后重新分配完整额度。

待成交订单占用风险和资金；同一日重复信号不释放已经亏掉的额度。交易风险、费用统计和账户收益分别记账，不以券商“购买力”当现金，不把风险 0.5%误写为仓位只有 0.5%。

这些分散、日亏和容量值属于新方案建议，确认实施不等于证明其盈利；由验证决定是否收紧或另提修订，绝不由 LLM 在盘中扩大。

## 11. 执行状态机与故障恢复

沿用唯一券商写入入口 scripts.monitor_modern_momentum_paper，在其内部接入新策略意图，不能另起一个可自由下单的 AI Agent。

```text
事件已记录 → 观察 → 结构就绪 → 预案已确认 → 风控通过 → 已提交
                                                       ↓
                               提交结果未知 → 查询/对账，禁止重复提交
                                                       ↓
部分成交/已持仓 → 保护已核实 → 退出中 → 已平仓且已对账 → 当日完成
```

订单幂等键由交易日、策略版本、symbol、事件簇、尝试序号和动作组成，使用券商允许长度内的稳定 hash。SQLite 唯一约束与单实例锁保证重启、重复调度、HTTP 超时不产生第二笔同意图订单。

提交前核实 Paper host、账户 ID 白名单、资金和风险预留；提交超时进入 UNKNOWN，先按 client_order_id 查询，不盲目重发。部分成交按真实数量建立/核验保护，检查子单是否已激活。若 broker bracket 对部分成交保护尚未激活，停止新增量，确认撤销未成交部分后保护或退出已成交量，不能假定提交 bracket 就已受保护。

主动平仓必须先确认与保护卖单不会重复执行：查询仓位、撤销冲突子单并确认、以实际剩余数量提交平仓；竞态时重新对账。禁止用无数量的泛化“卖出”造成净空头。保护单已成交时不重复平仓。

| 故障 | 自动动作 | 恢复条件 |
| --- | --- | --- |
| 单票报价过时/缺 K | 冻结该票新仓；记录具体数据年龄 | 连续 3 个新鲜检查、完成 K 无缺口、当前信号仍有效 |
| 全局行情断流/时钟偏差超 1 秒 | 冻结全部新仓；保留券商保护；重连/校时 | 连续 3 次新鲜检查、订单持仓一致、无权限错误 |
| 券商认证/账户不符 | 不重试写单，报警 | 凭据修复后独立校验；不得切到实盘作为替代 |
| 订单结果未知/仓单不符 | 冻结该票或账户新仓；只查证与保护处理 | 券商查询完成且持仓、活动订单、审计一致 |
| 新仓预案飞书或 Livermore 失败 | 预案未就绪，不下新单；持仓保护不受影响 | 获取去重后的真实回执并再次检查信号 |
| 成交通知失败 | 先记录本地 fill，继续保护，进入通知 outbox | 同一 fill 重试直到回执；不重复播报 |
| Loop 不可用或拒绝 | 本地复盘照常完成，保留待传任务与原因 | 合约/证据修复后按 revision 重试；不伪造必填字段 |
| 日亏触发/kill-switch | 当日不自动解锁；撤入场、有序退出 | 次日按规则或用户明确操作，不因行情恢复而重开 |
| 进程宕机 | 已提交的券商保护继续存在，任务监督器重启 | 先全量对账、后恢复观察；不直接恢复写单 |

自动修复只限预先测试的重连、重试、缓存重建和服务重启。未知代码 bug 报警并进入修复候选，不能让运行时模型自行修改线上代码后继续开仓。故障首次通知、状态升级再通知、恢复通知一次；不每分钟重复刷屏。

## 12. 每日复盘要交付什么

16:00 初报、16:20 终报采用同一 trade_date + revision。晚到费用或券商修订生成追加修正版，引用被替代版本；不会改写当时的决策与行情。

### 12.1 人看的中文 HTML + Livermore 摘要

1. 今日运行是否正常：触发时刻、进程版本、数据覆盖、断流、关键阻断。
2. 资金结果：Paper 原始已实现/未实现、费用、成本调整收益、账户对账差额、日最大回撤、资金利用率。
3. 每笔交易：何时知道消息、为什么买、什么条件成交、怎么退出、毛/净收益、MFE/MAE、策略版本、券商成交证据。
4. 未交易漏斗：发现事件数→可交易宇宙→数据完整→正期望候选→结构确认→风控通过→预案就绪→提交→成交；每层数量和首要失败原因。
5. Top10 漏选复盘：当时有无消息、是否在覆盖范围、何时可见、是否有可执行入场；不能用当日赢家要求上午必买。
6. 因子变化：3/5/10 日热度与净优势、负样本数、独立日数、区间宽度；样本不足明确写出来。
7. 可改进项：每项一个可证伪假设，不是“提高选股质量”这种空话。
8. Loop：stage-only 状态、远端 accepted/processing/completed/rejected、task/run ID、错误和下次重试。

### 12.2 机器看的完整复盘包

manifest 包含 event/decision/outcome/selection/execution 文件 hash、代码 SHA、policy hash、特征版本、成本版本、模型及 prompt 版本、时间区间、数据覆盖和审批证据。原始、修正、模拟和真实来源不能混写。

券商确认空仓且日内订单/成交查询完整，可产生“已核实零成交”包。没有运行与缺证据分别产生 operational_failure / evidence_incomplete 研究包，不把它们设成 accepted broker-backed review。

第一波消息保持用户认可的格式：“序号. 股票代码：中文催化，RVOL 两位，盘前带符号百分比两位”。内部枚举、长小数不外露。所有中文发送前 UTF-8 往返校验、拒绝 U+FFFD 和连续问号，发送后保存正文 hash 与 message_id。飞书不写逐秒行情。

## 13. 本地自进化：每日学习，每周实验，受控晋级

### 13.1 经验库的三个账本

- 事实账：原始新闻、行情、订单、成交和历史可见性，追加写，不由 AI 改写。
- 诊断账：漏选、假突破、退出过早、点差过宽、系统漏跑、通知延迟，引用事实 ID；AI 可以提出解释，也必须显示证据与反例。
- 策略账：实验假设、参数改动、对照版本、数据切分、成本、尝试次数、结果与晋级/拒绝理由。

有效市场/券商证据优先；用户反馈帮助发现问题；点击、满意度或抱怨不是收益标签。人工成交可以形成独立经验集，但缺决策时点证据时不能证明自动策略历史上会做同样交易。

### 13.2 学习频率

每天：更新成熟样本、校验漂移、汇总可重复故障、刷新次日统计。每周：最多 4 个新候选，每个只改一个主要假设，与 H15 和当前 champion 使用相同成本和资金约束比较。第一版不做遗传算法穷举，不在线自训大模型。

候选必须说明“预计改善什么、在哪类样本失败、何种结果否定假设”。旧失败样本回放和灾难场景作为记忆保留，不能只记最近盈利交易。每次实验登记在 registry，包含失败和被取消的尝试。

### 13.3 晋级与回滚

research → shadow → paper_canary → paper_champion；新算法/执行改动需代码 review 与显式发布。自动晋级仅适用于用户预先批准的参数空间内、通过下节门槛的候选；首次启用这一权限前仍须用户批准。风险、资金上限、券商端点、止损保护和审计规则不在可自动优化参数中。

gray rollout 建议：候选先占策略名义资金上限的 10%（20 万基数时最多 2 万），至少 5 个交易日且完成至少 10 笔可对账的买卖闭环用于操作验证；通过后到 25%，累计至少 10 日且 20 笔闭环再检查；完成不少于 30 个前向交易日、30 笔闭环与经济门槛后才可占全部授权额度。比例是资金上限而非必须投资，所有阶段保持相同比例风险约束。

灰度期间账户只有一个券商写入者，champion 与 challenger 的虚拟分配合计不超过账户限制。发生重复下单、保护缺失、未授权端点或净空头，立即暂停新仓；回滚只切换策略版本，先接管现有订单，不能把旧进程直接杀掉丢弃持仓。

## 14. 历史验证、盈利验收和防过拟合

### 14.1 三年回测计划

以可得到合格历史事件与报价的真实截止日向前取 36 个月；不足部分列出覆盖缺口，不说“完整三年”。默认最早 18 月训练、随后 6 月验证、随后 6 月滚动评估、最后 6 月封存盲测。最终分界用美股交易日清单写入 manifest，不按文件最后修改日期。

训练与评估边界剔除跨界事件簇，至少隔离一个交易日且覆盖最长标签持有期。特征拟合、阈值、标准化和成本分位数只用当时以前的数据。滚动评估可以逐月向前，只用过去训练；最后盲测版本固定、只开封一次。已经看过的盲测段不能继续叫盲测。

回测包括退市/更名/拆股、历史市值、无反应和失败事件；没有历史 first_seen 或真实 NBBO 的时期只能作为降级研究。存在同 K 线同时触发止损和止盈且无更细路径时，按保守止损优先或剔除并报告敏感性，不挑盈利路径。

回放与在线复用同一 feature/decision/risk 函数；只更换时钟和 broker/market adapters。必须模拟预案处理延迟、下一可用报价成交、部分成交、撤单超时和成交容量，不能信号一出就按理想价无限成交。

### 14.2 经济门槛（拟议，不代表已达到）

| 门槛 | 要求 |
| --- | --- |
| 最低证据量 | 验证/滚动评估合计至少 100 笔；封存盲测至少 30 笔且覆盖至少 30 个有决策的独立交易日。只是最低资格，区间不充分仍不能通过 |
| 净期望 | 封存盲测与前向 Paper 成本调整期望 >0；按交易日聚类 bootstrap 的均值 95% 下界 >0 |
| 盈亏结构 | 平均盈利/平均亏损 ≥1.2，净 PF ≥1.2；不强求胜率 >50% |
| 风险 | 组合回撤 ≤8%，无违反硬性订单安全规则；资金曲线包含空仓日 |
| 稳健性 | 分阶段、分事件、分流动性报告；1.5 倍基准可变执行成本情景净期望仍不为负；极端滑点另列 |
| 前向证明 | 至少 30 个前向交易日；原始 Paper 与附加成本后结果都展示，所有执行可对账 |
| 经营收益 | 除交易净收益，还单列扣除数据订阅、AI、服务器摊销后的系统经营净收益，不能隐去固定成本 |

这些门槛不能从数学上保证以后赚钱；样本小或经过大量选择时更不能。所有实验次数登记，多候选择优使用多重比较控制并报告选择过程。若没有策略通过，结论是“尚未验证”，继续研究而不是降低标准凑上线。

基准同时报告现金、SPY、QQQ：既报告相同交易窗口持有，也报告长期买入持有作为背景，统一时间/费用/本金；不把日内半仓年化与全天满仓指数年化直接作优劣结论。实际无数据不得虚构基准收益。

## 15. 外部 Loop 同步与候选策略接收

### 15.1 三类数据不混合

- Discovery：盘后 10:00—15:00 Top10、主因、覆盖、排名和研究标签。
- Decisions：盘前与盘中决策的真实冻结 cohort、当时输入、所有保留/拒绝原因、决策意图、状态转移。
- ExecutionReview：对应真实 Paper/用户实际成交证据的结果；来源保留。观察和研究回放不能顶替券商成交。

现有 quant_daily_review-v6 及新分支强调 Top10 cohort、SignalContract 和风险证据时间线；新事件模型不能自行假定远端已支持全部字段。实施先生成本地扩展包并运行兼容探测/契约测试。远端支持的部分按现有契约上传；不支持的部分本地 outbox 保留，提交接口变更需求，不填假记录绕过验证。

daily Top10 数量不足但旧接口强制 10 条时返回明确 cohort_incompatible，保留真实样本。已核实零成交若旧接口支持就正常传；若不支持则上传支持的研究通道，成交复盘通道等待接口协调。不把“缺成交证据”自动转成“未成交”。

### 15.2 上传状态机

prepared → local_validated(stage-only) → queued → submitted → remote_processing → remote_completed；另有 local_blocked / remote_rejected / retryable_failure。只有带远端最终成功证据才能在日报写“回传完成”。

幂等键为 trade_date + workflow_version + payload_kind + cohort_hash + revision；保存请求 hash、响应正文（脱敏）、task/run ID。网络失败按 1/5/15/60 分钟退避；永久 schema/证据错误进入修复队列，不无休止重新创建任务。

依次运行 scripts.sync_loop_daily_review --stage-only，然后真实提交，最后读取远端完成状态。stage-only 成功不得写“已上传”；POST 成功不得写“Loop 已学习”。明细错误需能指出缺哪个字段、对应哪条证据。

### 15.3 Outcome 与 challenger

1d/5d/20d 是研究观察窗口，用于评估题材后续影响，不是本策略持仓周期，也不能把后续上涨算成当天已实现利润。严格按交易日成熟，未满期不回填零。当前日内策略的主要交易标签仍为 15/30/60 分钟和实际退出结果。

Outcome 配置包含 QQQ 主基准、SPY 对照、成本模型 ID 与费率来源、生效时间、真实批准人和真实批准时间；其中基准和成本为本设计建议，未批准状态保持 pending_approval，不能自动写入用户姓名当批准。存在且校验通过、一次 stage-only 和真实端到端提交成功后，才启用相应定时同步开关。

Loop 返回策略先存 challenger.json，验签/来源、字段白名单、版本和适用日期校验后进入本地研究队列。外部候选没有直接写 active.json 或券商权限；不允许夹带脚本、关闭风控或改账户。当前只支持少量参数覆盖的 consumer 需显式扩展契约，不透传未知字段。

## 16. 部署、可观测性、备份与模型开销

### 16.1 单一事实来源

active policy 保存交易规则、风控、交易时刻、特征/成本版本；release manifest 保存代码 SHA、依赖 hash、数据路径、policy hash 和审批记录。环境变量仅保存连接、路径、环境开关和秘密，不再让交易阈值散落在 .env、脚本和定时提示中。

同一信号的研究回放、预案、在线风险、日报和 Loop 都引用相同 policy_id。启动时若不同模块读到不同值就阻断新仓并打印冲突来源。未知字段和错误 schema 不静默忽略。

### 16.2 部署方式

保持 Windows Task Scheduler + 一个持续运行的交易监督入口，启动时核实路径与单实例锁。复用 schedule.supervisor / schedule.modern_funnel 的调度能力，改为按市场时钟调度加盘中事件循环；不再增加按个股创建的聊天自动化。

部署流程：盘点活动目录修改→纳入隔离分支→单元/集成/故障演练→冻结依赖与 manifest→非交易时段部署不可变 release→先影子验证→Paper 灰度。main 只接受 review 后合并；不在运行目录 git pull 或热改代码。不移动旧数据，不擅自删除旧任务；切换时禁用经核实的重复写单入口。

### 16.3 可观测性和恢复

本地健康页/日报显示：最近事件时间、行情年龄、完成 K 边界、进程心跳、当前持仓、活动单、保护覆盖、最新预案回执、当日复盘和 Loop 状态。每个动作关联 trace_id、decision_id、client_order_id。

目标：每笔成交及费用可追溯；已知持仓保护覆盖 100%；同意图重复订单为 0；漏跑/认证失败在 2 分钟内报警；进程重启先对账再开仓。断网不能保证通知送达，保留本地待发与恢复补报。

订单和决策写入持久 SQLite WAL 后才推进状态；行情/事件按日 Parquet 与 manifest 保存。每日增量备份至独立存储目标，定期做恢复演练。独立备份位置未配置就显示 backup_unconfigured，不把同盘副本称为灾备。

秘密不写进报告、代码、Loop payload 或新闻 prompt。只访问专用飞书 Base，禁止旧 Base；所有外部输入按数据处理。LLM 无券商密钥、直接下单工具、shell 或 active policy 写权限。

### 16.4 一个实施模型，不是让大模型逐秒交易

建议唯一实施模型 GPT-6 Astra，medium，负责跨模块重构、测试、故障演练和交付。官方将其定位为复杂推理、编码和端到端工作模型，并列出 medium 支持；这支持工程选型，不证明交易盈利。[OpenAI 模型目录](https://developers.openai.com/api/docs/models)

运行时需要语义归因时，候选配置也可固定同一模型 ID，以较低推理强度处理受约束 JSON；归因缓存按新闻版本复用，不逐秒调用。运行模型切换必须重新做分类质量与延迟评估。推理延迟记入可决策时间，避免回测当成即时可用。

建议运行时 AI 预算上限 20 美元/交易日，作为待批准开销，未批准不开启新增付费任务。达到上限停止新增 AI 归因，保留已有有效判断和持仓保护；不编造分类。开发实施耗费与运行耗费分账。当前用户账户是否已开放所推荐模型仍需在选择器确认，本轮不自动切换。

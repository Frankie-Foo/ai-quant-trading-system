# 系统能力与成熟度审查

审查日期：2026-07-30
审查分支：`agent/consume-market-health-sse`

## 结论

当前工程已经形成“量化研究、盘中决策、受限模拟盘执行”的完整原型，但仍不能定义为成熟的无人值守交易产品。当前成熟度边界保持为：

- `stage=research_only`
- `paper_eligible=false`
- `live_eligible=false`
- `approved_for_live=false`

Paper 写入默认关闭，仓库中没有实盘 Broker 路由。

## 尚未真正完成

1. “自动选股 -> 自动生成不可变交易计划 -> 自动启动 Paper”还没有完整接通。Paper 执行器仍依赖人工准备的当日 JSON 计划。
2. 尚无经过验证的选股准确率。已有 PIT 会话和 OOS 框架，但净成本标签、真实报价成本覆盖率和 purged OOS 仍需继续积累。
3. 深度学习训练、新闻表征模型、图像/K线表征模型尚未进入正式训练与注册链路。
4. 手机成交截图、K线截图和手工笔记还没有正式上传、OCR、人工确认和复盘入库链路。
5. 盘中催化剂和红队仍可共用同一 DeepSeek 客户端，当前主要通过提示词和角色隔离，不是模型级独立红队。
6. LangGraph 目前只停留在选型设计层，未进入生产运行代码。
7. Agent 可以产生证据、教训、草案和沙盒实验，但不能自动修改生产参数。

## 工程审查结果

已修复的重点工程问题：

1. 自主执行器的日损、持仓数、总敞口和购买力需要统一入口校验。
2. 盘前撤单失败后的替换订单需要幂等保护，避免重复挂单或超卖冲突。
3. Agent 或推送故障时，应严格落实“有持仓则保护性退出、无持仓则空仓”的规则。
4. 客户端急停状态必须被执行器读取，不能只停留在本地界面状态。
5. 账户独占检查需要区分系统仓和手工仓，避免同票混淆。
